# SentinelAI — Data Pipeline & Flow Engine (Phase 1 Implementation)

## 1. Pipeline Overview

The SentinelAI Phase 1 data pipeline passively ingests raw network packet captures, extracts protocol header metadata without payload inspection, aggregates bidirectional 5-tuple sessions, computes comprehensive packet-size and flag statistics, and emits deterministic JSONL flow records.

```
+─────────────────────────────────────────────────────────────+
|               Passively Captured PCAP / PCAPNG              |
+─────────────────────────────────────────────────────────────+
                               │
                               ▼  (Streaming PcapReader)
+─────────────────────────────────────────────────────────────+
|               PacketParser (packages/ingestion)             |
|   - IPv4 & IPv6 Decoders                                    |
|   - L4 Headers: TCP, UDP, ICMP                              |
|   - Decoded TCP Flags: SYN, ACK, FIN, RST, PSH, URG, ECE, CWR|
|   - Payload length calculation                              |
+─────────────────────────────────────────────────────────────+
                               │
                               ▼  (Yields PacketMetadata)
+─────────────────────────────────────────────────────────────+
|        BidirectionalFlowAggregator (packages/flow_engine)   |
|   - Canonical symmetric 5-tuple key                         |
|   - Directional tracking (originator forward vs. backward)  |
|   - Online statistics (Welford's algorithm: min, max, std)  |
|   - TCP flag counter aggregation                            |
|   - Inactivity & active timeout management                  |
+─────────────────────────────────────────────────────────────+
                               │
                               ▼  (Materializes FlowRecord)
+─────────────────────────────────────────────────────────────+
|       UnifiedFeatureExtractor (packages/features)           |
|   - Network Features (rates, asymmetry, packet sizes)       |
|   - TCP Features (flag distributions, SYN/ACK ratio)        |
|   - Timing Features (inter-arrival jitter, burst count)     |
|   - DNS Features (Shannon entropy, DGA/tunneling metrics)   |
|   - TLS Features (SNI presence, JA3/JA4 fingerprints)       |
|   - Centralized FeatureRegistry (Version 1.0)               |
+─────────────────────────────────────────────────────────────+
                               │
                               ▼  (Emits FeatureVector)
+─────────────────────────────────────────────────────────────+
|                 Deterministic JSONL / Vector Output         |
|   - Canonical FeatureVector (typed & flattened representations)|
+─────────────────────────────────────────────────────────────+
```

## 2. Supported Input Formats

- **PCAP (libpcap format):** Standard packet captures (.pcap) generated by tcpdump, Wireshark, or Zeek.
- **PCAPNG (Next Generation format):** Modern capture files (.pcapng) with multi-interface metadata.
- **Modes:**
  1. *Offline Batch Mode:* High-speed stream reading using `PcapPacketSource`.
  2. *Replay Pacing Mode:* Timestamp-paced internal replay with configurable speed multipliers (`replay_speed`), without transmitting any packets to physical or virtual network interfaces.

---

## 3. Passive Packet Metadata Extraction

Extracted solely from packet headers without inspecting or decrypting application payloads:

- **Timestamps:** Preserves original microsecond/nanosecond capture timestamps in UTC.
- **Network Layer (L3):**
  - IPv4: Source and destination IP addresses.
  - IPv6: Native 128-bit addresses (e.g., `2001:db8::1`).
  - Malformed or non-IP packets (e.g. raw ARP, Spanning Tree) are safely discarded.
- **Transport Layer (L4):**
  - TCP: Source and destination ports, full decoded flag bitmask (`syn`, `ack`, `fin`, `rst`, `psh`, `urg`, `ece`, `cwr`), payload length.
  - UDP: Source and destination ports, payload length.
  - ICMP / ICMPv6: Protocol classification, zero payload inspection.
- **Wire Length:** Full recorded wire packet length in bytes.

## 4. 5-Tuple Flow Identity & Bidirectional Aggregation

### 4.1 Canonical Symmetric 5-Tuple Key
To ensure reverse-direction packets map to the identical logical flow:
$$\text{Endpoint}_1 = \min\left( (\text{src\_ip}, \text{src\_port}), (\text{dst\_ip}, \text{dst\_port}) \right)$$
$$\text{Endpoint}_2 = \max\left( (\text{src\_ip}, \text{src\_port}), (\text{dst\_ip}, \text{dst\_port}) \right)$$
$$\text{Canonical Key} = \left( \text{Endpoint}_1, \text{Endpoint}_2, \text{protocol} \right)$$

### 4.2 Directional Tracking
- The endpoint initiating the flow (first packet seen) is designated the **originator** (`source_ip`, `source_port`).
- The opposite endpoint is designated the **responder** (`destination_ip`, `destination_port`).
- Forward packets ($F$) match the originator endpoint.
- Backward packets ($B$) match the responder endpoint.

## 5. Flow Statistics Calculation

Each materialized `FlowRecord` contains:
- `flow_id`: Deterministic identifier based on endpoints, protocol, and start timestamp.
- `start_time` & `end_time`: First and last observed packet timestamps.
- `duration_sec`: Total active session duration in seconds.
- `total_packets`, `forward_packets`, `backward_packets`.
- `total_bytes`, `forward_bytes`, `backward_bytes`.
- **Packet Size Distribution:**
  - `min_packet_size`: Minimum wire packet length in bytes.
  - `max_packet_size`: Maximum wire packet length in bytes.
  - `mean_packet_size`: Arithmetic mean wire packet length.
  - `std_packet_size`: Numerically stable standard deviation computed via Welford's algorithm:
    $$M_{2, n} = M_{2, n-1} + (x_n - \mu_{n-1})(x_n - \mu_n)$$
    $$\sigma = \sqrt{\frac{M_{2, n}}{n}}$$
- **TCP Flag Counters:** Cumulative counts of observed `syn`, `ack`, `fin`, `rst`, `psh`, `urg`, `ece`, `cwr`.
- `termination_reason`: `tcp_fin`, `tcp_rst`, `inactivity_timeout`, `active_timeout`, or `end_of_input`.

---

## 6. Flow Lifecycle & Timeout Management

- **Inactivity Timeout:** Flows silent for longer than `inactivity_timeout_sec` (default: 30.0s) are flushed.
- **Active Timeout:** Continuous active flows exceeding `active_timeout_sec` (default: 120.0s) are flushed to ensure timely telemetry.
- **TCP Termination:** Handshakes ending with `FIN` or `RST` are tagged and cleanly retired.
- **End-of-Input Flush:** At EOF of a capture, `flush_all()` materializes and clears all remaining in-memory state, preventing memory leaks.

## 8. Passive-Security Guarantees

1. **Zero Egress:** No packets, pings, handshakes, or resets are emitted.
2. **Read-Only Descriptors:** PCAP/PCAPNG files are opened strictly in binary read mode (`"rb"`).
3. **Zero Decryption:** Cryptographic payloads are untouched.
